## Build & Run

```bash
# Build and run on Android emulator (primary target)
dotnet build FridgeScan/FridgeScan.csproj -f net9.0-android
dotnet run --project FridgeScan/FridgeScan.csproj -f net9.0-android

# Build for Windows (secondary target)
dotnet build FridgeScan/FridgeScan.csproj -f net9.0-windows10.0.19041.0
```

There are no test projects in this solution.

## Architecture

This is a **.NET MAUI cross-platform app** targeting Android, iOS, MacCatalyst, and Windows. It uses the **MVVM pattern** with **CommunityToolkit.Mvvm** source generators.

### Data flow

1. **Persistence**: All data lives in **Appwrite** (cloud BaaS at `fra.cloud.appwrite.io/v1`). There is no local database.
2. **In-memory cache**: `ProductsManager` (registered as singleton) holds an `ObservableCollection<Product>` that acts as the client-side source of truth. Views bind against this collection.
3. **Service layer**: `ProductService` handles CRUD against Appwrite's Tables API. It also logs activity via `ActivityService` (e.g., when a product is added). `ActivityService` writes to a separate Appwrite collection.

### Product inventory flow

- `ProductsPage` binds to `ProductsManager.Products` (the in-memory collection).
- On load, `ProductsViewModel` calls `ProductService.GetProductsAsync()` and passes results to `ProductsManager.Init()`.
- Mutations (add, update, delete) call `ProductService` which syncs to Appwrite, then updates the in-memory collection.
- Barcode scanning (`BarcodeScannerPage`) uses `BarcodeScanning.Native.Maui` and looks up products via the OpenFoodFacts API.

### Recipe aggregation

Multiple recipe sources are queried **in parallel** from `RecipeViewModel`:
- **Web scraping**: `RecipeGoodFoodService` and `GialloZafferanoService` (both implement `IRecipeService`) scrape BBC Good Food and Giallo Zafferano using HtmlAgilityPack.
- **AI generation**: `RecipeAiService` uses OpenAI via the LangChain SDK (`LangChain.Providers.OpenAI`) to generate recipe suggestions and full recipe details from available ingredients.

A named-resolution factory (`Func<string, IRecipeService>`) resolves the correct scraper for the recipe details page, keyed by `"goodfood"` or `"giallozafferano"`.

### Secrets

Secrets (API keys for Appwrite, OpenAI, Syncfusion license) are stored in a `secrets.json` file bundled as a raw asset (gitignored). The `Secrets` static class in `Keys.cs` loads this at runtime via `FileSystem.OpenAppPackageFileAsync`. This means secrets are embedded in the app package.

### Email import (incomplete)

`EmailService` and `ImportViewModel` exist as scaffolding for importing purchase emails via Microsoft Graph + MSAL, but `FetchPurchaseEmailsAsync()` currently returns an empty list.

### Key third-party dependencies

- **Syncfusion MAUI** (v32.1.20) — ListView, Cards, Expander, Inputs, Buttons, PullToRefresh, TabView. License registered in `MauiProgram.cs`. Excluded from Windows target due to PRI conflicts.
- **CommunityToolkit.Maui** (v12.3.0) — UI toolkit extensions.
- **BarcodeScanning.Native.Maui** (v2.2.1) — Camera-based barcode scanning.
- **LangChain** + **LangChain.Providers.OpenAI** (v0.17.0) — AI recipe generation.

### MVVM patterns

- ViewModels inherit from `BaseViewModel` (which inherits `ObservableObject`). They use `[ObservableProperty]` for bindable properties and `[RelayCommand]` for commands — both source-generated by CommunityToolkit.Mvvm.
- Views are XAML pages with code-behind. Each page resolves its ViewModel from the DI container in its constructor.
- Shell navigation (`AppShell.xaml`) defines a `TabBar` with 4 tabs: Products, Recipe, Import, Activities. A detail route is registered for `RecipeDetailsPage`.
- The app forces dark theme (`AppTheme.Dark`) and uses Syncfusion's `MaterialDark` theme.
- A bundled `grocery.json` (in `Resources/Raw/`) maps common grocery items to categories for autocomplete.

### DI registration (all singletons except pages)

Services: `ProductService`, `ActivityService`, `ProductsManager`, `RecipeGoodFoodService`, `GialloZafferanoService`, `RecipeAiService`, `JsonLdParser`, `EmailService`
ViewModels: `ProductsViewModel`, `RecipeViewModel`, `RecipeDetailsViewModel`, `ActivitiesViewModel`, `ImportViewModel`
Pages (transient): `ProductsPage`, `ImportPage`, `RecipePage`, `RecipeDetailsPage`
