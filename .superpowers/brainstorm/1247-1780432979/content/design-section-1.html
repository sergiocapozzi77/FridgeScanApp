Design Section 1: Data Model

The simplest model change to enable strikethrough

New model: IngredientItem

Currently Ingredients is List<string>. We'll add a lightweight wrapper:

// No changes to SavedRecipe model (persisted as-is)
public class IngredientItem
{
public string Name { get; set; }
public bool IsChecked { get; set; }
// Computed — drives strikethrough + opacity
[AlsoNotifyChangedFor(nameof(TextDecoration))]
[AlsoNotifyChangedFor(nameof(TextOpacity))]
partial void OnIsCheckedChanged(bool)
→ TextDecoration = value ? TextDecorations.Strikethrough : None
→ TextOpacity = value ? 0.5 : 1.0
}

ViewModel additions

// New observable collection for the view to bind to
public ObservableCollection<IngredientItem> IngredientItems { get; } = new();

// Populated in recipe load (after Recipe is set)
private void BuildIngredientItems()
{
IngredientItems.Clear();
foreach (var ing in Recipe.Ingredients)
IngredientItems.Add(new IngredientItem(ing));
}

// Tap command
[RelayCommand]
private void ToggleIngredient(IngredientItem item)
{
item.IsChecked = !item.IsChecked;
}

Numbering method steps

No model change needed — steps stay as List<string>. The numbering is handled entirely in the view template using the ItemIndex from the CollectionView (or a converter).
